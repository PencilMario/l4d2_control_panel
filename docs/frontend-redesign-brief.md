# L4D2 控制面板前端重设计说明

> 用途：作为 Gemini 生成新版前端设计稿的完整需求输入。
>
> 核心原则：保留现有全部功能，重做信息架构与视觉表达；界面文案以中文为主，不使用无必要的中英混排；同一概念始终使用同一个名称。

## 一、项目定位

这是一个面向单机部署环境的《求生之路 2》专用服务器运维控制面板。管理员通过浏览器管理多个游戏实例、共享游戏内容、插件包、私有文件、在线玩家、后台任务、游戏日志和自动维护计划。

产品不是面向普通玩家的社区网站，而是面向服务器管理员的高密度运维工具。设计应强调：

- 状态清晰：管理员能快速判断控制节点、游戏实例、后台任务和内容版本是否正常。
- 操作安全：停止、更新、删除、封禁等高风险操作必须有明确影响说明和二次确认。
- 过程可见：耗时操作必须显示排队、执行、进度、成功、失败和诊断入口。
- 信息高效：桌面端适合同时观察多个实例；移动端仍能完成关键管理操作。
- 术语统一：禁止同一对象在不同页面使用不同名称。

## 二、必须保留的产品能力

新版设计不能删减或弱化以下功能：

1. 管理员密码认证与安全会话状态。
2. 控制节点健康状态和异常提示。
3. 多个游戏实例的创建、配置、启动、停止、重新安装和永久删除。
4. 游戏实例的期望状态、实际状态、地图、玩家和性能观测。
5. 原生游戏控制台连接、实时输出、暂停跟随、继续跟随和命令发送。
6. 在线玩家列表、对局摘要、踢出玩家和永久封禁。
7. 共享游戏本体更新，以及在线玩家处理策略。
8. 共享 VPK 的上传、上传前清理、进度队列、下载、重命名和删除。
9. 插件包上传、GitHub 发布源管理、版本检查、热更新和完整更新。
10. 每个游戏实例的私有文件浏览、编辑、上传、导入、导出、移动、删除、暂存、差异查看、应用、快照恢复和文件历史。
11. 游戏日志分类浏览、预览、下载、轮转提示和保留策略。
12. 后台任务列表、筛选、进度、详细事件、实时日志、复制和下载。
13. 自动维护计划的创建、编辑、启用、停用、立即执行和删除。
14. Steam 安装凭据、GitHub 访问令牌、任务记录保留数量和游戏日志保留天数设置。
15. 加载、空数据、无权限、网络异常、任务失败、部分成功和重试状态。

## 三、统一术语

### 3.1 核心领域术语

| 统一名称 | 含义 | 禁止或避免使用 |
| --- | --- | --- |
| 游戏实例 | 独立配置、运行和管理的一台《求生之路 2》专用服务器 | 容器实例、服务器进程、节点实例 |
| 控制节点 | 运行控制面板服务并管理全部游戏实例的主机 | 控制平面、控制端、主节点混用 |
| 期望状态 | 管理员希望游戏实例保持的生命周期状态 | 配置状态、目标状态混用 |
| 实际状态 | 系统实时判断出的游戏实例运行状态 | 实时状态、当前状态混用 |
| 总览观测 | 游戏实例当前状态、玩家和性能信息的组合 | 监控快照、实例概览混用 |
| 性能指标 | 处理器、内存、网络、磁盘、进程数和运行时间等数据 | 性能评分、资源参数 |
| 当前带宽 | 当前采样区间内每秒接收和发送的数据量 | 实时流量、网卡带宽混用 |
| 累计网络流量 | 本次运行开始后累计接收和发送的数据量 | 当前带宽 |
| 性能历史 | 最近约一小时、每五秒采样的性能变化曲线 | 长期统计、审计数据 |
| 共享游戏本体 | 所有游戏实例共同使用的游戏安装内容 | 公共游戏、基础镜像 |
| 共享 VPK | 可供多个游戏实例使用的 VPK 内容文件 | 公共模组、共享插件 |
| 插件包 | 可部署到游戏实例的插件内容归档 | 插件版本、扩展包混用 |
| 私有文件 | 仅覆盖到一个游戏实例的文件工作区 | 私有层、覆盖层作为主界面名称 |
| 暂存更改 | 私有文件工作区中尚未应用到游戏实例的更改 | 未发布修改、草稿修改混用 |
| 应用更改 | 将暂存更改部署到对应游戏实例 | 发布、提交、同步混用 |
| 后台任务 | 由系统排队并持久执行的管理操作 | 作业、流水、工单混用 |
| 计划任务 | 按 Cron 表达式自动触发的后台任务 | 定时器、维护窗口混用 |
| 在线玩家策略 | 维护前遇到在线玩家时的处理规则 | 玩家处理模式、在线策略混用 |
| 游戏日志 | 游戏和插件运行期间产生并持久保存的日志 | 控制台日志、任务日志 |
| 任务日志 | 某个后台任务执行过程中产生的日志 | 游戏日志、运行日志混用 |

### 3.2 推荐界面用词

- 使用“处理器”，避免在标题中只写“CPU”；空间不足时可写“处理器占用”。
- 使用“进程数”，不要把进程数量标成“PID”。
- 使用“访问令牌”，不要单独使用“Token”。
- 使用“发布版本”，不要单独使用“Release”；“GitHub 发布源”可保留品牌名称。
- 使用“主机网络”，不要在中文句子中写“Host 网络”。
- 使用“游戏控制台”，不要仅写“控制台”，避免与浏览器开发者工具混淆。
- VPK、ZIP、Steam、GitHub、A2S、Cron 属于格式、品牌或协议名称，可以保留，但周围说明必须使用中文。
- 所有导航、标题、按钮、状态、帮助文案均使用中文，不再出现“OPERATIONS / OVERVIEW”“INSTANCE GRID”“CONTROL NODE”等装饰性英文。

### 3.3 状态词规范

- 游戏实例：运行中、已停止、启动中、停止中、故障、状态未知。
- 控制节点：在线、检查中、异常。
- 后台任务：等待执行、执行中、已成功、已失败、已取消。
- 上传任务：等待处理、本地清理中、计算校验中、上传中、已完成、失败。
- 内容状态：未初始化、就绪、版本未知、需要更新、待应用。
- 计划任务：已启用、已停用、尚未执行、未安排。

按钮应使用“动作＋对象”的明确格式，例如“创建游戏实例”“停止游戏实例”“应用更改”“下载完整日志”，避免仅写“确定”“处理”“操作”。

## 四、现有前端设计摘要

### 4.1 当前视觉基调

现有界面采用深色工业运维风格：

- 接近黑色的页面背景和深绿色面板。
- 高饱和黄绿色作为主强调色。
- 红色用于删除、停止和高风险操作。
- 琥珀色用于警告和需要关注的状态。
- 卡片、边框、细网格和等宽数字强化技术控制台感。
- 左侧固定导航，右侧为主工作区。
- 实例卡片信息密度较高，并直接嵌入性能曲线。

新版可以继承“深色、克制、专业、略带游戏工业感”的方向，但不要机械复刻现有布局。应提升层级、留白、可读性和操作聚焦，避免所有模块都使用相同边框造成视觉噪声。

### 4.2 当前主要问题

- 装饰性英文眉题与中文标题并列，形成明显中英混排。
- 页面标题、副标题和局部模块标题的语义层级不够统一。
- 总览实例卡片一次展示过多指标，重要状态和次要数据竞争注意力。
- 高风险操作与普通工具按钮距离较近，容易误触。
- 内容仓库同时承载游戏本体、VPK、插件包和发布源，页面较长且认知负担高。
- 私有文件、游戏日志和任务日志属于不同工作流，但视觉容器较为相似，需要更明确的上下文标识。
- 部分技术词直接以英文显示，不利于统一中文产品语言。
- 桌面端适合大屏，但新版需要进一步明确窄屏导航、抽屉、表格折叠和底部操作栏行为。

## 五、建议的信息架构

### 5.1 全局导航

建议保留七个一级入口，并统一为：

1. 总览
2. 私有文件
3. 内容仓库
4. 游戏日志
5. 后台任务
6. 计划任务
7. 系统设置

任务日志不单独占用一级导航。它是“后台任务”的详情页，通过返回按钮回到任务列表。

### 5.2 全局框架

桌面端：

- 左侧固定导航区，顶部显示产品标识“L4D2 控制面板”。
- 导航底部固定显示控制节点状态。
- 主工作区顶部包含页面标题、简短说明、安全会话和当前管理员标识。
- 全局错误使用页面顶部通知条；短暂成功反馈使用轻量提示。
- 耗时任务进入全局任务中心，不使用长时间阻塞页面的加载遮罩。

移动端：

- 左侧导航收进顶部菜单抽屉。
- 页面标题与主要操作上下排列。
- 关键提交操作可使用底部固定操作栏。
- 双栏文件管理器改为“目录抽屉＋内容区”。
- 宽表格改为卡片列表或可横向滚动区域，但不能隐藏关键状态和操作。

## 六、页面设计要求

## 6.1 管理员认证

目标：快速、安全地进入控制面板。

必须包含：

- 产品名称与用途说明。
- 管理员密码输入框。
- “进入控制面板”主按钮。
- 正在认证、认证失败、服务不可达状态。
- 不展示用户名输入，因为现有流程仅需要管理员密码。

设计建议：使用单列居中卡片，背景保持克制，不做营销式大幅插画。安全提示清晰但不制造恐慌。

## 6.2 总览

目标：在十秒内回答四个问题：控制节点是否正常、有多少实例运行、是否有玩家、是否有任务或内容需要处理。

### 顶部摘要

建议包含四到五个摘要卡：

- 运行实例：运行中数量／实例总数，依据实际状态统计。
- 在线玩家：全部实例当前玩家总数。
- 游戏实例：实例总数。
- 游戏本体版本：共享游戏本体当前版本。
- 待处理事项：失败任务、待应用插件包或异常实例数量；若无数据可省略。

### 游戏实例列表

每张实例卡必须展示：

- 游戏实例名称。
- 实际状态；必要时同时提示期望状态与实际状态不一致。
- 当前插件包及“待应用”状态。
- 当前地图和游戏模式。
- 在线玩家数与容量。
- 地址或端口摘要，包括游戏端口、电视转播端口和插件端口。
- 核心性能指标：处理器、内存、当前下载、当前上传、磁盘读写、进程数、运行时间、A2S 延迟、总占用空间。
- 最近约一小时的性能历史，可切换处理器、内存、网络和磁盘。
- 启动或停止游戏实例。
- 打开游戏控制台。
- 打开玩家列表。
- 打开实例配置。
- 永久删除游戏实例。

信息层级建议：

1. 第一层：名称、实际状态、主要操作。
2. 第二层：地图、玩家、插件包和异常提示。
3. 第三层：四个最关键性能指标。
4. 展开层：完整指标和性能历史。

不要默认把十项指标和完整曲线全部平铺在每张卡中。可使用“展开性能详情”降低首屏拥挤，但功能必须保留。

### 创建游戏实例

表单至少包含：

- 名称。
- 数据目录。
- 游戏端口。
- 电视转播端口。
- 插件端口。
- 启动地图。
- 插件包选择。
- 额外启动参数。
- 启动命令预览。

表单需要展示端口占用、路径无效、名称重复等错误。创建完成后通过后台任务反馈进度。

### 实例配置

与创建表单字段保持一致，使用同一字段顺序和术语。额外启动参数属于高级设置，建议默认折叠，并显示最终启动命令预览。

### 停止、重新安装和永久删除

- 停止：说明玩家会断开，提供“确认停止”。
- 重新安装插件包：显示当前插件包，可选择是否保留私有文件；说明影响和回滚边界。
- 重新安装游戏本体：属于高影响维护操作，必须说明全部相关实例可能受到影响。
- 永久删除：列出将删除的数据，要求输入完整实例名称确认；危险主按钮使用“永久删除”。

## 6.3 游戏控制台

目标：像本地终端一样稳定查看和操作原生游戏控制台。

必须包含：

- 当前游戏实例名称和连接状态。
- 实时日志输出，最多保留最近一千行显示数据。
- ANSI 颜色、时间、警告和错误高亮。
- 自动跟随最新输出。
- 用户向上滚动后暂停跟随，并显示“继续跟随”。
- 清空当前显示内容。
- 命令输入框和“发送命令”。
- 连接中、断开、重连和错误状态。

控制台建议使用全高抽屉或大尺寸对话框，不要使用狭小弹窗。

## 6.4 在线玩家与对局摘要

必须包含：

- 当前地图、游戏模式、对局分数或摘要。
- 玩家名称、平台标识、加入时长、延迟等可用信息。
- 踢出玩家。
- 永久封禁玩家。
- 空服、查询失败和数据刷新状态。

踢出确认需说明玩家会立即断开。永久封禁确认需说明封禁持续到管理员手动解除。危险操作不要依赖颜色作为唯一提示。

## 6.5 内容仓库

建议使用页内标签或清晰分区，分为“游戏本体”“共享 VPK”“插件包”“GitHub 发布源”，避免一个超长页面连续堆叠。

### 游戏本体

显示：

- 当前版本。
- 保存位置。
- 初始化或迁移状态。
- “更新游戏本体”操作。
- 在线玩家策略：有玩家时跳过、等待玩家离开、强制执行。
- 更新影响说明和最近任务入口。

游戏本体是共享资源，不应要求选择单个目标实例。

### 共享 VPK

必须支持：

- 多文件选择和拖放上传。
- 每个文件选择“直接上传”或“上传前清理”。
- 一键将全部文件设为同一种处理方式。
- 清理过程、校验过程、上传进度、实时速度、平均速度、预计剩余时间。
- 完成后显示清理移除项数、原始大小、最终大小和节省比例。
- 失败重试和取消。
- 文件下载、重命名和删除。
- 空状态“暂无共享 VPK”。

上传队列应是可持续查看的区域，页面切换后仍能理解任务状态。

### 插件包

必须支持：

- 上传 ZIP 插件包。
- 显示名称、来源、版本、文件名、大小和兼容能力。
- 区分“支持热更新”和“需要完整更新”。
- 选择目标游戏实例。
- 执行热更新或完整更新。
- 删除插件包。
- 标记实例当前使用版本和待应用版本。

完整更新需要明确说明会停止游戏实例、替换插件包并在失败时保留诊断记录。热更新需要明确说明不会主动停止或重启实例，但不兼容时不会自动降级为完整更新。

### GitHub 发布源

必须支持：

- 添加和编辑发布源。
- 字段：源名称、GitHub 仓库、发布资源匹配规则。
- 检查最新版本。
- 删除发布源。
- 显示检查中、没有新版本、下载中、已登记插件包和失败状态。

## 6.6 私有文件

目标：提供接近轻量代码编辑器的实例私有文件工作区。

### 页面顶部

- 目标游戏实例选择。
- 刷新。
- 新建文件。
- 新建目录。
- 上传文件。
- 导入 ZIP。
- 导出 ZIP。
- 历史快照。
- 移动端“打开文件目录”。

### 文件目录

- 树形目录展开和收起。
- 文件或目录选中状态。
- 编辑文本文件。
- 移动、删除和下载。
- 空目录提示。
- 不支持文本编辑的文件展示类型、大小和更新时间。

### 文件编辑

- 文件路径和内容编辑区。
- “保存到暂存区”。
- 离开未保存内容时提醒。
- 大文件或不支持编辑时提供下载，不强行加载编辑器。

### 暂存与应用

底部固定状态栏显示：

- 工作区是否与已应用版本一致。
- 未应用更改总数。
- 新增、修改、删除数量。
- 展开查看暂存差异。
- “应用更改”主按钮。
- 应用排队、执行、成功和失败状态。

### 历史能力

- 应用快照列表和恢复操作。
- 单文件历史版本列表。
- 恢复前说明覆盖范围。
- 没有快照或历史时显示明确空状态。

## 6.7 游戏日志

必须包含：

- 目标游戏实例选择。
- 日志目录树。
- 按“游戏日志”和“插件日志”分组。
- 日志文件大小和修改时间。
- 文本预览、警告和错误高亮。
- 超长日志截断提示。
- 日志轮转或删除提示，并提供刷新。
- 下载完整日志。
- 加载、空目录、无日志和读取失败状态。

桌面端使用目录树与预览区双栏布局；移动端目录树进入抽屉。

## 6.8 后台任务

目标：管理员能快速定位正在运行、失败或需要诊断的任务。

### 任务列表

必须包含：

- 状态筛选。
- 任务类型筛选。
- 刷新。
- 任务类型、目标对象、状态、创建时间、开始时间、完成时间和执行用时。
- 执行中任务的阶段说明和进度条。
- 任务失败摘要。
- 展开任务事件。
- 打开任务日志。
- 没有任务时的空状态。

任务状态使用文字、图标和颜色三种方式共同表达。

### 任务日志详情

必须包含：

- 返回任务列表。
- 任务名称、任务编号和当前状态。
- 日志搜索。
- 来源筛选。
- 级别筛选。
- 复制当前日志。
- 下载完整日志。
- 实时跟随与“继续跟随”。
- 早期日志因容量上限截断的提示。
- 没有符合条件日志的状态。

## 6.9 计划任务

必须支持以下任务类型：

1. 游戏更新。
2. 插件热更新。
3. 插件完整更新。
4. 仅同步 GitHub 发布源。
5. GitHub 发布版本热更新。
6. GitHub 发布版本完整更新。
7. 私有文件备份。
8. 过期文件清理。

每个计划显示：

- 任务类型。
- 目标游戏实例或全局目标。
- Cron 表达式。
- 时区。
- 在线玩家策略。
- 启用状态。
- 上次执行时间。
- 下次执行时间。
- 编辑、启用或停用、立即执行、删除。

新建或编辑计划时，根据任务类型动态显示：

- 目标游戏实例。
- GitHub 发布源。
- 在线玩家策略。
- 保留天数等任务参数。
- 任务影响、执行步骤、中断范围、所需参数和风险说明。

提供独立“任务类型说明”对话框，完整解释八种任务的目标、步骤、中断影响、参数和注意事项。删除计划必须二次确认。

在线玩家策略统一为：

- 有玩家时跳过。
- 等待玩家离开。
- 强制执行。

## 七、交互与反馈规范

### 7.1 操作等级

- 主要操作：每个页面最多一个高强调按钮，例如“创建游戏实例”“上传 VPK”“新建计划”“应用更改”。
- 次要操作：刷新、编辑、下载、查看日志等使用普通按钮或图标按钮。
- 危险操作：停止、删除、永久封禁使用红色语义，并与普通操作保持间距。
- 不可逆操作：必须展示影响范围，并要求二次确认；永久删除游戏实例还需输入实例名称。

### 7.2 后台任务反馈

创建、更新、应用、清理、备份等耗时操作统一进入后台任务：

1. 提交中。
2. 已加入队列。
3. 执行中，显示阶段和进度。
4. 已成功，提供结果摘要。
5. 已失败，提供错误摘要和任务日志入口。

不要让按钮无限显示“处理中”。页面刷新后仍应从后台任务恢复真实状态。

### 7.3 空状态

空状态必须说明原因和下一步，例如：

- 暂无游戏实例：提供“创建游戏实例”。
- 暂无共享 VPK：提供“上传 VPK”。
- 暂无后台任务：说明执行管理操作后会在此显示。
- 暂无游戏日志：说明实例尚未生成日志或日志已清理。
- 暂无历史数据：说明性能历史会在实例运行后开始记录。

### 7.4 错误状态

- 页面级错误使用顶部错误通知，并提供关闭或重试。
- 区块级错误留在对应区块，不要只使用全局提示。
- 表单错误靠近字段显示，并保留用户已填写内容。
- 部分成功必须展示成功、去重和失败数量。
- 查询失败不能被解释为空数据，尤其是在线玩家策略判断。

### 7.5 无障碍

- 所有图标按钮必须有中文可访问名称和悬停提示。
- 状态不能只通过颜色表达。
- 键盘可访问导航、表单、对话框、文件树和日志工具栏。
- 对话框打开后锁定焦点，关闭后焦点返回触发按钮。
- 支持减少动态效果偏好。
- 正文和关键数据满足深色背景下的对比度要求。

## 八、视觉系统建议

### 8.1 风格方向

关键词：深色运维、战术仪表、克制工业感、高信息密度、清晰层级、可靠、冷静。

避免：

- 常见人工智能生成的紫蓝渐变玻璃风。
- 大面积霓虹发光。
- 过度圆润的消费级卡片。
- 装饰性英文、伪终端代码和无意义坐标编号。
- 所有模块都使用同等粗重边框。
- 牺牲可读性的超小字号。

### 8.2 色彩建议

可保留现有黄绿色识别色，但建立更完整的语义体系：

- 页面背景：近黑绿色或中性炭黑。
- 一级面板：略亮于背景，形成稳定层次。
- 主强调色：黄绿色，用于当前导航、主要按钮和健康状态。
- 信息色：冷蓝色，用于链接、查看和普通信息。
- 警告色：琥珀色，用于待应用、策略警告和截断提示。
- 危险色：柔和红色，用于停止、删除、封禁和失败。
- 文本：高亮正文、普通正文、辅助说明、禁用文本四级。

酸绿色只用于重要位置，避免整页同时出现大量高亮。

### 8.3 字体与数字

- 中文正文使用清晰的无衬线字体。
- 版本号、端口、文件路径、Cron 表达式、日志和性能数字使用等宽字体。
- 大标题不使用过度压缩或装饰字体。
- 最小正文建议不低于十二像素，关键表单和说明不低于十四像素。

### 8.4 组件形态

- 圆角保持小到中等，突出工具属性。
- 卡片通过背景层级和间距区分，不完全依赖描边。
- 表格行支持悬停和选中，但不使用花哨动画。
- 数据指标优先使用“名称＋数值＋辅助说明”，避免复杂仪表盘。
- 性能曲线保持细线、低噪声网格和明确图例。
- 对话框按风险分为普通、警告和危险三种视觉等级。

## 九、响应式断点建议

- 大屏桌面：一千四百四十像素及以上。总览可显示两列实例卡片，内容仓库可双栏。
- 普通桌面：一千零二十四至一千四百三十九像素。总览以单列或紧凑双列呈现。
- 平板：七百六十八至一千零二十三像素。收窄导航，复杂表格转卡片或横向滚动。
- 手机：七百六十七像素及以下。导航抽屉、单列布局、文件目录抽屉、底部关键操作栏。

响应式设计不能通过隐藏功能实现。所有功能在手机上仍可到达，高风险确认和日志查看仍需完整可用。
